# 使用说明

## 1. 启动本地生成服务

在项目根目录执行：

```powershell
$OutputEncoding = [Console]::OutputEncoding = [Text.UTF8Encoding]::new($false)
dotnet run --project "src/GeneratorService"
```

目的：启动本机 HTTP 服务，让 WPS 插件可以调用生成能力。

原因：WPS 插件只负责界面，Excel 生成、SQLite 查询、AI 调用、授权校验都在本地服务完成。

## 2. 检查服务是否正常

浏览器打开：

```text
http://127.0.0.1:5188/api/health
```

看到 `success: true` 就说明服务已经启动。

## 3. 打开控制面板

当前 MVP 控制面板文件：

```text
src/WpsAddin/index.html
```

可以先用浏览器打开测试。后续正式接入 WPS 时，把这个页面迁入 `wpsjs create` 创建的任务窗格工程。

## 4. 单份生成

在控制面板填写：

```text
工程名称：XX项目
施工单位：XX建设
监理单位：XX监理
分部工程：主体结构
分项名称：钢筋安装
施工部位：3层梁板
模板文件：钢筋安装检验批.xlsx
```

点击“生成当前资料”。

生成文件会输出到：

```text
Export/
```

## 5. 批量生成

切换到“批量生成”，新增或修改行后点击“批量生成”。

目的：一次生成多份检验批资料。

原因：工程资料实际使用时通常按楼层、部位、日期批量处理。

## 6. 知识库维护

知识库文件：

```text
KnowledgeBase/quality.db
```

核心表：

```text
quality_items
```

规范占位符只能从这张表查询，AI 不参与规范生成。

## 7. 模板维护

模板目录：

```text
Templates/
```

当前模板：

```text
Templates/钢筋安装检验批.xlsx
```

模板占位符示例：

```text
{{静态:工程名称}}
{{规范:主控项目表}}
{{AI:申请语}}
{{系统:当前日期}}
```

生成时程序会复制模板并修改副本，原模板不会被修改。

## 8. AI 配置

默认 `EnableAI` 为 `false`，系统使用本地兜底文本。

如需启用 DeepSeek：

1. 复制 `config.example.json` 为 `config.json`。
2. 设置：

```json
{
  "EnableAI": true,
  "DeepSeek": {
    "ApiKey": "你的API Key"
  }
}
```

目的：只让 AI 生成申请语、验收意见等自由文本。

原因：规范条文、允许偏差、检查方法不能由 AI 生成。

## 9. 授权说明

当前 MVP 支持试用授权：

```text
未激活时允许生成 20 次
```

`/api/license/status` 会返回机器码 Hash。当前版本已经支持 RSA 签名激活码，同时兼容旧版 Base64(JSON) 激活码，便于平滑升级。

当前仓库已经提供离线激活码生成工具：

```text
src/LicenseTool
```

交互式生成：

```powershell
$OutputEncoding = [Console]::OutputEncoding = [Text.UTF8Encoding]::new($false)
dotnet run --project "src/LicenseTool"
```

命令行生成示例：

```powershell
$OutputEncoding = [Console]::OutputEncoding = [Text.UTF8Encoding]::new($false)
dotnet run --project "src/LicenseTool" -- --machine-code-hash "对方机器码Hash" --license-type year --expire-date 2027-12-31 --modules generate,batch,ai --version 3.0
```

工具会输出两部分：

```text
激活码 JSON
激活码 Base64
```

发给用户的是 `激活码 Base64` 那一整串文本。

## 10. LicenseTool 发布

如果你希望以后不用进入源码目录运行 `dotnet run`，可以直接把发码工具发布成独立 exe。

发布命令：

```powershell
$OutputEncoding = [Console]::OutputEncoding = [Text.UTF8Encoding]::new($false)
dotnet publish "src/LicenseTool/LicenseTool.csproj" -c Release -o "publish/LicenseTool"
```

发布目录：

```text
publish/LicenseTool/
├── LicenseTool.exe
└── 其他运行时文件（若有）
```

目的：把开发期工具整理成可直接双击或命令行调用的发码程序。

原因：以后你给客户发码时，不需要再依赖源码目录，也不需要重新编译。

发布后首次运行：

```powershell
$OutputEncoding = [Console]::OutputEncoding = [Text.UTF8Encoding]::new($false)
cd "D:\YY\编程\工程资料制作"
.\publish\LicenseTool\LicenseTool.exe --generate-keypair
```

生成激活码示例：

```powershell
$OutputEncoding = [Console]::OutputEncoding = [Text.UTF8Encoding]::new($false)
cd "D:\YY\编程\工程资料制作"
.\publish\LicenseTool\LicenseTool.exe --machine-code-hash "对方机器码Hash" --license-type year --expire-date 2027-12-31 --modules generate,batch,ai --version 3.0
```

注意：

- `Keys/license-private.pem` 只保留在你的电脑
- `Keys/license-public.pem` 要跟客户端一起发布
- 你发给客户的是输出结果里的 `激活码 Base64`

## 12. WPS JS 工具

本机已安装的 `wpsjs` 版本：

```text
wpsjs 2.2.3
```

如果当前 PowerShell 提示找不到 `wpsjs`，可以重开终端，或先用完整路径：

```powershell
$OutputEncoding = [Console]::OutputEncoding = [Text.UTF8Encoding]::new($false)
& "C:/Users/ljj/AppData/Roaming/npm/wpsjs.cmd" --version
```

目的：确认 WPS 加载项脚手架工具可用。

原因：npm 全局命令安装后，旧终端可能还没有刷新 PATH。

## 13. 常见错误：GeneratorService.exe 应用程序错误

如果双击 `GeneratorService.exe` 出现：

```text
应用程序发生异常 未知的软件异常 (0xe0434352)
```

最常见原因是服务已经启动过一次，第二次启动时端口 `5188` 被占用。

检查是否已经启动：

```powershell
$OutputEncoding = [Console]::OutputEncoding = [Text.UTF8Encoding]::new($false)
Get-Process | Where-Object { $_.ProcessName -like "GeneratorService*" }
```

停止已有服务：

```powershell
$OutputEncoding = [Console]::OutputEncoding = [Text.UTF8Encoding]::new($false)
Get-Process | Where-Object { $_.ProcessName -like "GeneratorService*" } | Stop-Process -Force
```

然后再启动：

```powershell
$OutputEncoding = [Console]::OutputEncoding = [Text.UTF8Encoding]::new($false)
& "D:/YY/编程/工程资料制作/publish/GeneratorService/GeneratorService.exe"
```

目的：避免重复启动同一个本地服务。

原因：本地服务固定监听 `http://127.0.0.1:5188`，同一台电脑同一时间只能有一个进程占用这个端口。
